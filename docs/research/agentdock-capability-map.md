# AgentDock capability plan

> Planning document, not an implemented feature. Planning entry: [#52](https://github.com/ChiJiun/agentdock/issues/52). Related: [M2.5 Self-hosting #51](https://github.com/ChiJiun/agentdock/issues/51), [upstream fork sync #53](https://github.com/ChiJiun/agentdock/issues/53), [main protection #55](https://github.com/ChiJiun/agentdock/issues/55).

Goal: a cross-project, multi-agent, Windows-first and local-first workbench that reuses existing Claude Code/Codex over ACP, Git, CI, build caches and open-source modules, so repeated builds, tests, reviews and context handoffs cost less. Each capability must be testable and shippable on its own, without one large new framework.

Baseline and status (checked against main `c9e33cf`):

- main has the React preview, the Frontend workflow and the Task/Session/Event contracts of [ADR-0003](../decisions/0003-task-session-event-contracts.md) under [`docs/contracts/`](../contracts/README.md) (PR #22, merged; the ADR status line there still reads Proposed). Those contracts own Task/Session/Event, state transitions and ACP capability boundaries.
- The backend is Rust-primary. Rust implementation packets are in `docs/tasks/` of [PR #68](https://github.com/ChiJiun/agentdock/pull/68), together with ADR-0004; neither is merged yet, so cite them as proposed.
- The Node runtime PRs #25, #27, #28, #29 and #33 stay unmerged. They are behaviour and test references only and do not enter main. Rows below cite them for scenarios, not as code to reuse.
- Nothing in this file claims a capability is implemented. Prototype, merged code and release evidence each have their own status.

## Scope of the table and the Alpha gate

The phases are a first split, not an approval of every row. For each row, #52 still has to record requirements, alternatives, build/buy/integrate/defer, upstream code and license, interface and data model, security boundary, dependencies, estimate, tests and acceptance before Feature Issues are split. The whole table is not an Alpha release blocker.

[#51](https://github.com/ChiJiun/agentdock/issues/51) is the only complete Alpha gate: a Windows install, real Claude Code and Codex, two worktrees, persisted session events, verifiable tests, Git diff and PR, permission approvals, and ten real tasks without data loss. AgentDock may be used to develop AgentDock step by step; compare 20 to 30 tasks before it replaces the existing tools. Local CI cache, the full integration queue and remote workers do not block v0.1.0-alpha.

## Server-side authority and upstream retention

- AgentDock's local branch policy, agent review and Git hooks protect controlled operations only. They cannot replace GitHub server-side rulesets and branch protection, which [#55](https://github.com/ChiJiun/agentdock/issues/55) tracks. A single maintainer must not configure a required human approval count that nobody can satisfy, and a ruleset change needs repository administration permission, which a successful docs PR does not prove.
- The four forks (Worktrunk, Orca, AgentBridge, Orkestra) are development copies that keep their own feature branches and may carry upstream PRs. The planned weekly sync (#53, PR #58 not merged) uses fast-forward only and never force-pushes. They are not a mirror: Git mirrors, bundles, NAS and off-platform snapshots are excluded by the owner, and a fork does not keep upstream Issues, PRs or release assets. Pinned SHAs and LICENSE/NOTICE records stay in [sources.md](../sources.md#upstream-source-retention); a fork update never changes an AgentDock dependency by itself.

## Upstream reuse

See the [Local-first SDLC design](local-first-multiagent-sdlc.md) for the Local CI, cache and integration queue contracts.

The [source manifest](../sources.md#upstream-source-retention) and [#53](https://github.com/ChiJiun/agentdock/issues/53) give the immutable URLs, SHAs and paths. Their source and license records are starting points for dependency-closure review.

- Worktrunk (MIT/Apache-2.0), `src/git/repository/worktrees.rs` and `src/commands/merge.rs`. Evaluate the Git/Worktrunk CLI, including external Git, hooks and Windows paths. Use Orca (MIT), `src/main/git/worktrees/removal/worktree-removal-preflight.ts`, as a behavior/test reference for Electron/Node-dependent worktree cleanup.
- AgentBridge (MIT), `src/agentbridge/validation/runners.py`, and Orkestra (Apache-2.0), `src/orkestra/verify/binding.py` and `src/orkestra/kernel/dag.py`. Reference Python runner and dependency boundaries for the Rust contracts. Privileged execution, immutable evidence and scheduling stay with AgentDock.
- Nx (MIT), `packages/nx/src/project-graph/affected/affected-tasks.ts` and `packages/nx/src/tasks-runner/cache.ts`. Integrate through installed Nx CLI only on opted-in Nx projects. Its JS workspace, plugins and native modules make single-file transplantation unsuitable.
- Jujutsu (Apache-2.0). Defer optional CLI integration and keep the fixed source tree. Validate Git interoperability and conflict/evidence semantics before introducing a second VCS backend.
- Use the planned SQLite store through the planned Rust Host, the existing React frontend, native agent runtimes over ACP and OS SSH as integration boundaries. Code indexing, OS isolation and release tooling still need source spikes to verify exact commits, files and dependencies before selection. No paid dependency is selected by this plan.

## Validation and decisions

Each of the five candidate areas under #52 (cross-project code understanding and reuse, versioned project memory, cross-repo orchestration, OS-level sandbox, ongoing efficiency benchmark) must be decided as V1, V2 or Defer and as build, buy or integrate, with measurable acceptance. A research issue does not approve implementation. Code reuse, handoff and benchmark are evaluated first for early benefit. The sandbox risk boundary cannot wait until untrusted commands are allowed.

The follow-up issues under #52 define independent acceptance for [code indexing](https://github.com/ChiJiun/agentdock/issues/59), [handoff](https://github.com/ChiJiun/agentdock/issues/60), [cross-repo recovery](https://github.com/ChiJiun/agentdock/issues/61), [OS isolation](https://github.com/ChiJiun/agentdock/issues/62), [release provenance](https://github.com/ChiJiun/agentdock/issues/63) and [local data portability](https://github.com/ChiJiun/agentdock/issues/64). The existing UI and accessibility design continues under #56. Routing and budget controls continue under #13 and #43.

The Alpha evidence comes from #51 and #14. For V1, run the same revision and test set in isolated worktrees with cold/warm cache and queue disabled/enabled. Include a failed test, stale base and an unknown project fixture. Compare wall time, CI minutes, false passes and interventions. Treat changes in tested scope as invalid comparisons.

The table records planning decisions. Detailed estimates and candidate dependency closures are open and should be assigned in #52 before implementation. Record unresolved integration choices as ADRs with an owner and a verification fixture.
