# P1-1: Cargo workspace, pinned toolchain and lint baseline

> **繁中摘要**：在 repo 根目錄建立 Rust workspace，固定 toolchain 為 1.91.1，統一 lint 設定，並建立第一個空殼 crate `agentdock-core`，讓 `cargo fmt/clippy/test` 在乾淨的 checkout 上通過。不碰 Tauri、CI、領域型別與前端。模型等級：一般模型可。

Issue: #4 | Gate (#51): G1 (reproducible build) | Model tier: **standard model**

## 1. Goal and non-goals

Goal: a Rust workspace at the repo root with a pinned toolchain, shared lints, and an empty `agentdock-core` crate, so `cargo fmt/clippy/test` pass on a clean checkout.

Non-goals: Tauri (P1-2), CI (P1-3), domain types (P2-1), other crates (their packets create them). No frontend changes.

## 2. Prerequisites and parallel work

- Prerequisites: none.
- Parallel: none (root of every Rust packet). After it, P1-2 and P1-3 can run in parallel.

## 5. Implementation steps

1. `rustup --version`. If rustup is missing, stop and ask the owner (CONVENTIONS §1). With rustup present, the first `cargo` command in the repo installs 1.91.1 at user level from `rust-toolchain.toml`; that is expected.
2. Create the files above.
3. `cargo generate-lockfile`, then run the §7 commands.
4. `git status` shows only the §3 files.

## 11. Common mistakes and pitfalls

- `channel = "stable"`: different machines get different compilers; breaks "reproducible build".
- If a later packet cannot compile because a crate's MSRV exceeds 1.91, bump the pinned channel to a specific newer version in that PR and explain why (never `stable`).
- Do not choose an open-source license; the owner has not decided (ADR-0002 §5).
- Do not add `[profile.release] panic = "abort"` or similar; decided at packaging time (P9-1).
